File Role Key Details

3. GitHub Actions Workflow (.github/workflows/api-tests.yml)

name: API Test Automation

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]
  workflow_dispatch:

jobs:
  api-tests:
    name: Execute API Automation Tests
    runs-on: ubuntu-latest

    steps:
      - name: Checkout Repository
        uses: actions/checkout@v5

      - name: Set Up Python
        uses: actions/setup-python@v6
        with:
          python-version: "3.12"

      - name: Install Dependencies
        run: |
          python -m pip install --upgrade pip
          pip install -r requirements.txt

      - name: Verify Dependencies
        run: |
          python --version
          python -m pytest --version
          pip show allure-pytest

      - name: Debug Test Collection
        run: |
          ls -la
          ls -la tests/
          python -m pytest tests --collect-only -vv

      - name: Run API Tests
        env:
          TEST_ENV: staging
          CLIENT_ID: ${{ secrets.CLIENT_ID }}
          CLIENT_SECRET: ${{ secrets.CLIENT_SECRET }}
        run: |
          python -m pytest tests -vv -s --alluredir=allure-results

      - name: Upload Allure Results
        if: always()
        uses: actions/upload-artifact@v5
        with:
          name: allure-results
          path: allure-results/
          if-no-files-found: warn
          retention-days: 14

4. Key Alignment Fixes

  • Workflow YAML indentation: Each - name: under steps: must be indented by 2 spaces so GitHub Actions parses the workflow without syntax errors[cite: 5].
  • APIClient methods & auth: Ensure APIClient supports post() (used by UserClient.create_user) and optional auth (for BearerTokenAuth)[cite: 6, 11, 12].
  • user_client fixture: Define user_client in tests/conftest.py so test_users.py resolves its fixture cleanly[cite: 1, 3].
  • Schema vs. API response: Make role optional (str | None = None) or match your target API's payload so Pydantic validation does not fail unexpectedly[cite: 3, 13].
